# Capability matrix: bawbel and three other scanners, measured offline

Report only. Nothing here changes the scanner. No tool is ranked, and the report draws no conclusion about the tools relative to each other. Every cell is tagged VERIFIED, SOURCED or UNVERIFIED. Tool versions, commands and dates are named. Run on 2026-11-25 (UTC), bawbel at commit `0ddf560`. Generated by the scripts named at the end; no count is typed.

## What was run

149 fixtures, one skill directory each: 147 are one `example_patterns` entry of an active AVE record (45 records), and 2 are this repository's own test fixtures. The AVE examples are one line of text under the same minimal frontmatter for every tool. By the record's layer: content 35, server_card 15, runtime 60, registry_metadata 37. The corpus file has sha256 `7d3284314f7ea19af096df2b20e9d715b628a398cf88391d97be90a1ae074e74`. Each tool was installed in its own scratch virtualenv with the network on, then run with the network disabled (`docker run --network none`), in its static or no-LLM mode, on harmless text that is only read. A tool that needs a network would have failed or fallen back, and that is a result. The bawbel run with Semgrep also set `SEMGREP_SEND_METRICS=off` and `SEMGREP_ENABLE_VERSION_CHECK=0`, because with Semgrep's default settings and no network that engine did not run in a test of it.

Times are wall-clock seconds for one process per fixture, including start-up. The runs shared one machine and some ran at the same time, so the times show the order of magnitude of each tool on that machine and do not compare the tools with each other.

A fixture is **flagged** when the tool reported at least one finding above INFO. This is the same rule for every tool. Policy findings such as a missing licence field are INFO and do not count.

## What this report does not show

- Any ranking, any comparison of the tools with each other, and any claim about real skills. The fixtures
  are one-line examples from AVE records and this repository's tests.
- Any tool's LLM, meta-analyzer or cloud mode. Only static or no-LLM modes were run, offline.
- Snyk Agent Scan's behaviour. It was not installed or run.
- Cisco's `behavioral` analyzer, SkillSpector's dependency inspection and the optional engines of every tool.
- Other versions of any tool. A newer release may differ.

## Not verified

- The README statements cited as SOURCED, apart from the flags and fields that `--help` or a run confirmed.
- Whether a fixture's wrapper (the frontmatter) changes any tool's result. It is the same for every tool.
- Timings under no load. The runs shared a machine.

## How to run it again

```text
python3 -I scripts/competitive_fixtures.py --corpus CORPUS.json --repo . --out fx
# in a scratch virtualenv per tool, with the network disabled for the run:
python3 -I scripts/competitive_run.py --tool bawbel --fixtures fx --out bawbel-core.json -- bawbel scan {path} --recursive --format json
python3 -I scripts/competitive_run.py --tool skillspector --fixtures fx --out skillspector.json -- skillspector scan {path} --no-llm --format json
python3 -I scripts/competitive_run.py --tool cisco --fixtures fx --out cisco.json -- skill-scanner scan {path} --format json
python3 -I scripts/competitive_render.py --manifest fx/manifest.json --results *.json --bawbel-ref "$(git rev-parse HEAD)" --date "$(date -u +%F)"
```

The corpus and the tools are inputs and are not committed. The per-fixture results, with rule names and
severity words and no tool output, are in `docs/reports/competitive-results/`.
